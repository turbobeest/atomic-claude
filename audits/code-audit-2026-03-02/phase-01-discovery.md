| 1 | phases/phase_01_discovery/tasks/task_109_closeout.py | M3 (Data Integrity) | MEDIUM | Closeout marks `corpus.json` as CRIT failure on greenfield projects where no reference materials exist | 69 | Task 101 returns True without creating `corpus.json` when no reference materials are found (task_101 line 189-201). | 2 | phases/phase_01_discovery/tasks/task_109_closeout.py | M3 (Data Integrity) | MEDIUM | Closeout marks `approaches.json` as CRIT failure when user never invokes the "generate" command during task 105 | 72 | In task_105, `approaches.json` is only created when the user explicitly types "generate" (task_105 line 304). This is a normal usage path -- the user may reach consensus without explicitly generating formal approaches. | Change the approaches.json check from "CRIT" to "BLCK", or generate a minimal approaches.json from the consensus data at the end of task 105. |
| 3 | phases/phase_01_discovery/tasks/task_104_opening_dialogue.py | E5 (Error Handling / JSON Parse) | MEDIUM | JSON parse failure from LLM synthesis silently falls through to fallback without informing the user that synthesis data may be incomplete | 592 | If the LLM returns malformed JSON (partially valid, or with trailing text after the JSON object), `json.loads(content)` raises `json.JSONDecodeError`. The exception is caught on line 593, logged at debug level, and a generic fallback synthesis with "Not fully captured" / "Not discussed" values is used. The user sees "Conversation synthesized" (line 315) with no indication that their multi-turn dialogue was not actually captured. The confirm prompt on line 325 shows placeholder values, but a user who presses Enter accepts garbage synthesis that propagates to tasks 105-109. | After falling back to the default synthesis, print a visible warning (not just debug log) indicating synthesis failed and the user should review the placeholder values carefully. Alternatively, retry the LLM call once before falling back. |
| 4 | phases/phase_01_discovery/tasks/task_105_discovery_work.py | E5 (Error Handling / JSON Parse) | MEDIUM | Same silent fallback pattern for consensus JSON generation | 776 | If the LLM returns malformed JSON for the final consensus in `_generate_consensus`, the code silently falls back to a hardcoded consensus with "Phased Implementation" as the approach and "Start with MVP" as a key decision (lines 780-789). | 5 | phases/phase01/orchestrator01.py | C3 (Configuration / Path) | MEDIUM | `OUTPUT_DIR` default path computed at module import time from `ATOMIC_ROOT`, which itself defaults to `Path.cwd()` | 46-47 | If the orchestrator module is imported before the working directory or `ATOMIC_ROOT` environment variable is set (e.g., during test collection, or when imported by a tool that later changes cwd), `OUTPUT_DIR` captures the wrong base path. Since `ATOMIC_ROOT` and `OUTPUT_DIR` are module-level globals evaluated at import time, any subsequent changes to the environment variable or working directory are not reflected. The `run_phase()` function passes these stale paths to `run_phase_tasks()` and all 9 task wrappers. | Compute `ATOMIC_ROOT` and `OUTPUT_DIR` inside `run_phase()` at call time rather than at module import time, or accept them as parameters to `run_phase()`. |
| 6 | phases/phase_01_discovery/tasks/task_101_entry_validation.py | A7 (API Contract) | MEDIUM | `_flatten_config` mutates and overwrites `project-config.json` without backup during auto-flatten | 287-301 | When `project.name` is absent but `extracted.project.name` exists (line 100-106), `_flatten_config` is called. It modifies `config_data` in-place and writes it back via `write_json`. If the `extracted` data is malformed or contains unexpected structures, the original config is overwritten with no backup. A partial write failure (disk full, permissions) could leave the config file corrupted, blocking all subsequent phases. | Create a backup of the config file before overwriting, or write to a temporary file and rename atomically. |
